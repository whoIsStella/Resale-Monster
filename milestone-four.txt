Read `AGENTS.md`, `README.md`, all database models and repositories, orchestration services, worker and scheduler code, API routes, configuration, migrations, and tests.

Implement Milestone Four: resale-domain inventory operations, product research workflows, MCP tools, agent-safe proposals, and human approval queues.

## Objective

Add the first real resale-domain capabilities to Goliath while preserving strict separation between:

1. read-only data access
2. agent-generated recommendations
3. human-approved proposals
4. deterministic execution

This milestone must not perform live marketplace publishing, repricing, delisting, refunds, buyer messaging, payouts, or credential access.

## Architecture principle

Agents may:

* inspect inventory
* research products
* generate listing drafts
* calculate pricing recommendations
* identify stale inventory
* create structured proposals
* request approval

Agents may not:

* mutate live marketplace listings
* contact buyers
* accept offers
* issue refunds
* purchase shipping labels
* access payout systems
* access raw marketplace credentials
* execute unrestricted SQL

Goliath must validate, persist, audit, and authorize every proposal.

### 13. Research job workflow

Implement an end-to-end product-research workflow:

1. inventory item enters `research_needed`
2. research job is created
3. eligible agent is selected
4. agent reads inventory and image metadata
5. agent records sources and candidate identifications
6. agent submits a structured result
7. result is validated
8. confidence threshold is evaluated
9. a proposal is created
10. human review is required for exact identification below the configured threshold
11. approved identification updates the inventory item
12. audit events are appended throughout

Do not allow a research agent to directly update final identification fields.

### 14. Listing-generation workflow

Implement an end-to-end draft workflow:

1. inventory item must satisfy required data checks
2. master draft is generated
3. deterministic validators run
4. marketplace variants are generated
5. warnings and missing fields are persisted
6. an approval proposal is created
7. reviewer approves, rejects, or requests revision
8. approved drafts remain drafts only

No marketplace publishing is allowed.
