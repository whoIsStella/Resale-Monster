## Architecture requirements

Each scheduled workflow must:

* create a normal persisted job
* run through the existing durable worker
* use the existing lease and heartbeat mechanisms
* use retry and backoff policies
* support crash recovery
* carry an idempotency key
* produce audit events
* appear in the existing jobs API and CLI
* respect marketplace-account boundaries
* respect emergency stops
* respect account-level and operation-level circuit breakers
* return controlled skipped results for unsupported adapter capabilities

Do not execute marketplace operations directly inside the scheduler.

The scheduler should only create durable jobs. The worker must claim and execute them.

## Job payload requirements

Every marketplace job must include, where applicable:

* marketplace account ID
* marketplace name
* operation type
* scheduled timestamp
* schedule ID
* policy version
* idempotency key
* retry configuration
* correlation or trace ID
* requested capability
* write/read classification

Persist these values in existing job metadata or typed schemas. Do not place raw cookies, tokens, browser state, buyer-private payloads, or secrets in job records.

## Idempotency requirements

Duplicate scheduler ticks must not create duplicate jobs.

Use a deterministic idempotency key based on values such as:

* schedule ID
* operation type
* marketplace account ID
* normalized scheduled time window

A repeated tick for the same account, operation, and schedule window must resolve to the existing job.

Retries of an existing job must reuse the same operation idempotency key.

Write operations must continue using gateway-level idempotency and read-back verification.

## Emergency-stop behavior

When a global, account-level, or operation-level emergency stop is active:

* marketplace write jobs must not execute
* blocked jobs must record a controlled blocked or skipped result
* no adapter write method may be called
* safe read-only synchronization and reconciliation jobs may continue
* stop decisions must be auditable
* lifting a stop must not cause duplicate writes

Classify every scheduled operation explicitly as read-only or write-capable.

## Circuit-breaker behavior

Circuit breakers must isolate failures by marketplace account and operation.

Requirements:

* one failing account must not block unrelated accounts
* one failing operation must not block unrelated operations
* open breakers prevent affected write execution
* half-open probes run through persisted jobs
* successful probes close breakers
* failed probes reopen breakers with backoff
* breaker decisions are audited

## Unsupported adapter behavior

The current browser marketplace adapters are intentionally unsupported or read-only skeletons.

For unsupported capabilities:

* do not guess behavior
* do not attempt browser fallback outside the typed adapter
* do not report success
* produce a controlled skipped or unsupported result
* preserve the job record and audit event
* do not repeatedly retry permanent unsupported-capability results

Fake adapters must support deterministic tests for all required workflows.
